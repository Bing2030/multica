The `multica` binary is a small **daemon manager**. It no longer has commands for issues, agents, workspaces, projects, squads, skills, autopilots, auth, or config — all of that lives in the [web UI](/issues) now. The binary only starts and stops the [daemon](/daemon-runtimes), reports its status, and upgrades itself.

The daemon reads its configuration from `~/.multica/config.json` — a JSON file you create by hand. There is no `multica setup` or `multica login` to generate it for you. See [Cloud quickstart](/cloud-quickstart) or [Self-host quickstart](/self-host-quickstart) for the exact field values to use for each backend.

## Configuring the daemon

The daemon reads `~/.multica/config.json` at start. The file has three fields:

| Field | Purpose |
|---|---|
| `server_url` | WebSocket URL of the Multica server, e.g. `wss://multica.example.com/ws` (self-host same-machine default: `ws://localhost:8080/ws`) |
| `app_url` | Frontend URL the daemon pairs with, e.g. `https://multica.example.com` (self-host same-machine default: `http://localhost:3000`) |
| `token` | A personal access token (PAT) prefixed with `mul_`, created under **Settings → Personal Access Tokens** in the web UI |

Minimal self-host example:

```json
{
  "server_url": "ws://localhost:8080/ws",
  "app_url": "http://localhost:3000",
  "token": "mul_..."
}
```

<Callout type="tip">
Create the PAT in the web app under **Settings → Personal Access Tokens** and paste it into the `token` field. See [Authentication and tokens](/auth-tokens) for the difference between PATs, JWT cookies, and daemon tokens.
</Callout>

## Daemon commands

| Command | Purpose |
|---|---|
| `multica daemon start` | Start the daemon (background by default; add `--foreground` to run in the foreground) |
| `multica daemon stop` | Stop the daemon |
| `multica daemon restart` | Restart the daemon |
| `multica daemon status` | Check whether the daemon is online and its concurrency |
| `multica daemon logs` | View daemon logs (add `-f` to follow) |
| `multica daemon disk-usage` | Show disk usage of the daemon's working directories |

For how the daemon works under the hood — runtimes, heartbeats, offline handling — see [Daemon and runtimes](/daemon-runtimes).

## Version and self-update

| Command | Purpose |
|---|---|
| `multica version` | Print the binary version |
| `multica update` | Upgrade the binary to the latest release |

## Getting full flags

Every command supports `--help`:

```bash
multica daemon start --help
multica daemon logs --help
```
